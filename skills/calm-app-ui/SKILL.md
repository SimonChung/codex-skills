# 清雅多語 App UI 設計

從使用者在這個畫面想完成的事開始。先找出做決定前需要看的資訊、最常用的動作，以及完成後會看到的結果。沿用專案的品牌、原生導覽習慣、元件與語言資源。平台或語系尚未指定時，用平台中立的規格起稿，可用繁體中文與英文做排版樣本，標明實際支援語系待定。

## 建立清雅的視覺層次

- 用對齊、留白與字級區分層次。同一組內容對齊閱讀起始緣，組內距離小於組間距離。列表先試單一平面，獨立操作或需要一起移動的內容才加卡片。
- 每個任務區讓最重要的動作或選取狀態優先取得視覺焦點。閱讀頁可以讓標題與內容主導。次要動作用文字或較輕的外框，圖示容易有歧義時保留文字標籤。小圖示可維持視覺尺寸，點按區域依平台規範擴大。
- 沒有品牌色時，可從暖白松綠開始。指定低彩度淺藍時，採用下表的霧藍配色。相同用途的元件沿用同一欄的配色，換色或製作深色主題時，重新檢查實際前景與背景的組合。

| 用途 | 暖白松綠 | 低彩度淺藍 |
| --- | --- | --- |
| 頁面與內文 | 暖白 `#F8F7F3` 底搭墨色 `#242B28` | 霧白 `#F4F7F9` 底搭墨藍 `#253947` |
| 日期、說明等次要資訊 | 暖白底搭灰綠 `#56635D` | 霧白底搭灰藍 `#506371` |
| 主要按鈕 | 松綠 `#356451` 底搭白字 `#FFFFFF` | 霧藍 `#B9CFDD` 底搭墨藍字 `#253947`，以石板藍 `#4F6A7D` 描邊 |

例如設計霧藍版語言選擇頁時，一般選項沿用頁面底色，已選列鋪冰藍 `#DCE8EF`，並在文字尾端顯示石板藍勾號。將較深的霧藍留給「套用語言」按鈕。鍵盤焦點使用與元件留有間距的石板藍外框，讓目前焦點和已選語言可以分辨。

- 優先使用支援系統字級的字體樣式。確認各語系的字型回退、行高與上下留白能容納漢字及附加符號。一般內文以至少 4.5:1 的對比為設計基準。錯誤、選取與焦點都要有顏色以外的線索，例如錯誤文字、勾選記號或焦點框。[W3C 文字對比說明](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)

## 讓同一套元件容納不同語言

- 用真實文案決定排版。標題、按鈕與錯誤提示允許換行和增高。寬度不足時，將標籤和值改成上下排列，並排按鈕依平台慣例改為垂直排列。保留操作名稱、閱讀順序與觸控範圍。例如「儲存草稿」換成「Save as draft」後，若與「捨棄變更」同列已放不下，就讓兩個按鈕各占一列。
- 將可見文案、圖示的無障礙名稱與系統回饋納入語言資源。沿用專案的鍵名慣例，以完整訊息交給翻譯。變數可換位，數量交由各語系的複數規則處理。例如 `library.savedCount` 可對應「已收藏 {count} 本書」與英文的「1 saved book／2 saved books」。實作採用框架支援的訊息格式。[Unicode ICU 訊息格式指南](https://unicode-org.github.io/icu/userguide/format_parse/messages/)
- 日期、數字與金額交由平台按地區格式化。保留資料本身的幣別與時區語意。語系選擇及翻譯缺漏沿用專案的回退順序，確認畫面顯示可讀文案。若需求包含手動切換，以語言自稱標示選項，例如「繁體中文」與「English」，並保留當前頁面和輸入內容。
- 版面以閱讀方向的起點與終點定位。支援從右到左（RTL）的語系時，檢查返回箭頭、導覽順序與焦點移動。商標及內容圖片維持原方向。阿拉伯文中夾有訂單編號、電子郵件等內容時，用平台的雙向文字機制隔離插入值，確認標點與編號順序。

## 交付與驗收

依要求交付畫面、規格或實作。做設計稿時，可用同一筆內容並列代表性語系，標出元件何時換行或改排。做實作時，把可翻譯內容接到既有 i18n 資源。檢視既有畫面時，指出問題出在哪個元件、哪個語系或字級，以及可採用的修正。

優先檢查本次畫面最容易失效的組合。

| 情境 | 通過條件 |
| --- | --- |
| 最窄支援寬度 × 最長標籤 × 放大系統字級 | 主要操作仍完整可讀、可到達，文字不互蓋，必要時可捲動。 |
| 資料清單從空白變為一筆、多筆或載入失敗 | 數量文案符合語法。空狀態提供適合的下一步，可重試的錯誤有清楚入口。 |
| 有支援 RTL 或可切換語言 | 導覽、焦點與閱讀順序一致。切換後標籤和格式更新，進行中的任務可以繼續。 |

沒有完整翻譯時，可用偽本地化拉長文字或測試 RTL，將結果標成模擬。可執行的原型以實際呈現與操作記錄結果。靜態設計稿標出需要實機確認的項目。[Android 偽本地化測試說明](https://developer.android.com/guide/topics/resources/pseudolocales)
