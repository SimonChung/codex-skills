# SBOM 與漏洞檢查

產生可追溯至來源或實際產物的套件清單，搭配漏洞資料庫檢查，交付結果及可重複執行的流程。SBOM 本身不是安全掃描通過證明。

## 範圍與既有流程

- 先讀專案指示、鎖檔、Dockerfile／建置設定與既有安全腳本，確認使用者要「檢查」、「修復」或「加入後續檢查」。沿用原任務已授權的修復與部署範圍；建立或執行檢查本身不代表要部署服務。
- 優先維護及執行專案現有腳本，例如 `scripts/verify-sbom.ps1`。先確認它的實際行為、輸入、輸出及副作用，不因檔名含 SBOM 就假定完整可信。
- 沒有現有流程時，依實際技術組合選擇工具。Go／Node／Docker 與 Windows PowerShell 的做法見 [references/go-node-docker.md](references/go-node-docker.md)。其他語言使用能辨識該鎖檔／產物的掃描器；工具不支援時明列缺口。
- 維持技能可跨專案使用：映像名稱、路徑、套件管理器、基底 OS、必要元件與嚴重度政策均從當前專案取得。沒有 npm、Ubuntu 或 Docker 的專案不必為了套用範例新增這些依賴。

## 產生與驗證 SBOM

1. 建立當次獨立輸出目錄，記錄掃描時間、來源／鎖檔雜湊、工具版本與漏洞資料庫時間。沿用可用且受支援的工具；新引入或更新掃描器時查核官方版本並固定版本，容器工具另記錄 digest。
2. 列出檢查層次：來源相依、開發／建置套件、實際執行檔或映像及其 OS 套件。多階段建置的最終映像常沒有前端建置工具，須另查來源鎖檔。明列沒有檢查的層次。
3. 使用掃描器產生 CycloneDX 或 SPDX，不手寫或推測套件版本。若只收到既有 SBOM，先確認格式與 provenance；沒有來源或映像可對照時，標示「僅掃描提供的 SBOM，完整性未核對」。
4. 依專案應有內容檢查套件名稱／版本或 purl、直接及開發相依，以及掃描結果中的生態系與 OS。不能只以 JSON 可解析、元件數大於零或掃描器回傳 0 判定完整；對確實沒有 OS 套件的 scratch 映像，改核對應有執行檔／語言元件。
5. 掃描原始清單與實際產物。重用舊 SBOM 前必須確認它對應本次來源與不可變產物 ID；來源在驗證期間改變則重新檢查受影響產物。

## 漏洞與通過條件

- 預設 High／Critical 為阻擋門檻，包含尚無修正版的項目；使用者或專案有明確門檻時依其政策執行並記錄。
- 既有、明確且有效的風險例外須連同識別碼、理由及期限呈現；不能把排除後的數字描述為沒有漏洞。不要自行新增忽略清單、排除開發相依或套用 `--ignore-unfixed` 來取得通過結果。
- 分別處理「找到漏洞」與「檢查未完成」。工具／網路／資料庫失敗、錯誤 JSON、缺報告、缺應有套件或不支援的 OS 都不能視為零漏洞；自動流程須回傳非 0。
- Go 呼叫可達性分析可補充實際暴露資訊，不能以「未呼叫」偷偷移除版本掃描命中。對誤判、套件別名及重複 CVE／GHSA 核對來源，不把未核實的猜測當成修復。
- 報告區分「npm 所有嚴重度合計為 0」與「映像 High／Critical 為 0」。結論只適用於當次範圍與資料庫時間。

## 修復及建立後續流程

- 已獲授權修復時，從官方公告／套件 registry 確認修正版與相容性，更新必要套件和鎖檔；可由套件管理器移除已不需要的相依。避免無關功能或全系統升級。
- 按變更執行既有功能、建置及必要整合測試，再掃描最終相依與產物。不得把純建置成功當作部署或實際外部操作驗證。
- 加入流程時，將可重複的命令落在專案腳本／既有 CI，並依使用者要求更新專案指示及文件。不要僅留下這次手動掃描結果，也不要虛構不存在的 CI 服務。
- 以新的候選產物建置及檢查，全部通過後才更新「已驗證」標籤。若原任務包含部署，部署的必須是該不可變 ID，不能在通過後重新建置另一份產物。後續檢查失敗時不得沿用舊的通過狀態冒充本次成功。
- 新增或修改阻擋流程時，在隔離測試位置驗證正常通過、已知高風險套件、掃描器故障及缺少應有內容的處理；確認失敗不覆蓋已驗證標籤或觸發部署。測試不應重啟正式服務。

## 資料及交付

- 掃描只提供需要的鎖檔、來源或新建置產物，排除 `.env`、憑證與無關資料。不要匯出含執行環境金鑰的容器設定或將其寫入 SBOM／日誌。
- 優先本機掃描；套件 audit 沿用專案核准的 registry。若使用外部掃描服務或上傳完整 SBOM，需在既有授權範圍內。Docker 掃描可使用映像封存檔，避免不必要的 daemon socket 掛載。
- 產物預設保存在忽略版控與 build context 的報告目錄，保存 SBOM、漏洞 JSON、步驟 log、狀態摘要、來源／產物識別與資料庫資訊。掃描失敗時亦留下原因及已完成部分。
- 最後簡述修復內容、各範圍的漏洞結果、功能驗證及未完成項目，附本機報告與可重跑指令。若有部署，另核對實際執行的映像 ID 與健康狀態；未部署就如實說明檢查結果。
